# ТЗ: Мобильное приложение TeminaFit

## 1. Цель документа

Описать требования к **мобильному приложению** TeminaFit:  
подогнать весь дизайн под телефон (удобно и красиво на маленьком экране), сохранить работу **ИИ-тренера** в точности как на сайте (распознавание поз, подсчёт повторений, подсказки по технике).

Дополнительно используется общее ТЗ: **ТЗ_перенос_в_приложение.md** (API, модели, квесты, логика упражнений).

---

## 2. Общие требования к приложению

- **Платформа:** iOS и/или Android (нативное или кроссплатформа: React Native, Flutter, Kotlin Multiplatform и т.п.).
- **Backend:** существующий Django-сервер; приложение общается с ним по HTTPS (те же API, что и сайт).
- **Язык интерфейса:** русский (все тексты, подсказки ИИ, кнопки, ошибки).
- **Офлайн:** по возможности кэшировать профиль и последние данные; при отсутствии сети — понятное сообщение; локально посчитанные повторения при наличии локального детектора можно сохранять и синхронизировать при появлении сети.

---

## 3. Дизайн под телефон (mobile-first)

### 3.1. Референс стиля (как на сайте)

Сохранить визуальную идентичность с сайтом TeminaFit:

- **Фон:** тёмный `#0D0D10`, градиенты фиолетовый/бирюзовый (как в `base.html` и `training.html`).
- **Акценты:** градиент `#A855F7` → `#D946EF` (кнопки, заголовки, прогресс); дополнительно циан `#06b6d4`, зелёный `#22c55e`, оранжевый `#f97316`, красный `#ef4444` для статусов и ошибок.
- **Карточки:** полупрозрачный фон `rgba(255,255,255,0.04)`, граница `rgba(255,255,255,0.08)`, скругления 12–20px.
- **Шрифт:** Outfit (или системный sans-serif, близкий по характеру).
- **Свечение:** лёгкое свечение для акцентных элементов (кнопки, активные пункты меню).

### 3.2. Адаптация под мобильный экран

- **Безопасные зоны:** отступы с учётом `safe-area-inset` (вырез, индикатор, жесты) на всех экранах.
- **Минимальный размер зоны нажатия:** не менее 44×44 pt (iOS HIG) / 48×48 dp (Material) для всех интерактивных элементов.
- **Крупные заголовки:** основной заголовок экрана — не менее 22–24 pt, жирный; подзаголовки 15–17 pt.
- **Читаемость:** основной текст не менее 15 pt; второстепенный — 13–14 pt, цвет приглушённый (muted).
- **Одна колонка:** на телефоне контент в одну колонку; списки (тренировки, квесты, статистика) — вертикальные карточки с достаточными отступами.
- **Нижняя навигация (рекомендуется):** 4–5 пунктов (Главная/Дашборд, Тренировки, Квесты, Статистика, Профиль). Иконки + подпись; активное состояние — акцентный цвет/подсветка.
- **Верхняя панель:** компактная: логотип/название, при необходимости кнопка «Назад» или меню; высота с учётом safe area.

### 3.3. Список экранов и требования к вёрстке

| Экран | Адаптация под телефон |
|-------|------------------------|
| **Вход / Регистрация** | Поля на всю ширину с отступами; кнопки во всю ширину или центрированные; ссылка «Регистрация»/«Войти» под основной кнопкой. |
| **Главная / Дашборд** | Блок приветствия (уровень, XP, серия входов) — карточка; ниже — 2 колонки или список «быстрых действий» (тренировки, квесты); карточки с отступами 16–20 pt. |
| **Тренировки (список)** | Сетка 1 колонка или 2 узкие карточки; у каждой — иконка, название, краткое описание, кнопка «Начать»; отступы между карточками 12–16 pt. |
| **Экран тренировки (камера + ИИ)** | См. раздел 4. |
| **Квесты** | Список карточек: название, описание, прогресс (progress/goal), награды; кнопки «Взять»/«Отменить»/«Завершить» с достаточным размером. |
| **Статистика** | Сводка сверху (числа крупно); ниже — табы или сегменты (день/неделя/месяц); графики/списки адаптированы по ширине, без горизонтального скролла по контенту (только внутри графика при необходимости). |
| **Профиль** | Аватар/уровень сверху; блок навыков (сила, выносливость, ловкость, техника) — сетка 2×2 или список; кнопка прокачки; достижения — список или сетка иконок. |
| **Лидерборд** | Список строк (место, имя, метрика); при необходимости фильтр по типу рейтинга. |
| **Настройки** | Группы настроек (учётная запись, тема, уведомления); выход — отдельная заметная кнопка. |
| **Конструктор тренировки** | Пошаговый диалог: один вопрос на экран, крупные кнопки ответов или поля ввода; в конце — экран с планом (список упражнений + рекомендуемые повторения). |

Все экраны должны визуально соответствовать референсу (цвета, карточки, типографика) и не иметь горизонтального скролла всего экрана (кроме явно заданных областей).

## 4. Экран тренировки с камерой и ИИ (критичный экран)

Этот экран должен вести себя и выглядеть так же по смыслу, как на сайте: камера, подсчёт в реальном времени, подсказки ИИ.

### 4.1. Расположение элементов на телефоне

- **Верх:** компактная полоска: название упражнения, кнопка «Выход» (назад). При необходимости — индикатор «Идёт запись» / «Камера активна».
- **Центр:** область камеры (превью с камеры) на всю доступную ширину, соотношение сторон сохранять (например, 4:3 или 3:4 в портрете). Допустимо рисовать поверх скелет (MediaPipe) опционально.
- **Поверх видео (оверлей):**  
  - Крупный **счётчик повторений** (или секунды для планки) — хорошо читаемый, контрастный (например, белый с тенью или в стиле сайта).  
  - При необходимости — таймер длительности тренировки.
- **Ниже видео (или поверх в нижней части):** блок **подсказок ИИ**:  
  - Одна строка **feedback** (общий статус: «Почти правильно», «Опускайся ниже» и т.д.).  
  - Список **ошибок** (до 2–4 на экране), каждая в формате: **«Что не так»** + **«Как исправить»** (message + hint из API); приоритет по полю `priority`.  
  Оформление — как на сайте: карточка/панель с фоном, граница зелёная/оранжевая/красная в зависимости от типа (success/warning/danger).
- **Внизу экрана:** кнопки **Пауза** и **Сохранить** (минимальная высота 48 dp, хорошо нажимаемые). Сохранить отправляет результат на `/api/workouts/complete/` и закрывает/возвращает на список тренировок.

### 4.2. Работа ИИ — как на сайте

ИИ должен работать **идентично** сайту:

1. **Получение позы:**  
   На устройстве получать **33 ключевые точки MediaPipe Pose** в реальном времени (через нативный MediaPipe SDK под iOS/Android или через WebView с тем же JS, если выбран гибридный вариант).

2. **Отправка на сервер:**  
   Периодически (например, каждый кадр или каждый N-й кадр, 10–30 fps) отправлять **POST** запрос на  
   **`/api/ai/process-landmarks/`**  
   с телом:
   ```json
   {
     "exercise_type": "PUSHUP" | "SQUAT" | "CRUNCH" | "PLANK" | "PULLUP",
     "landmarks": [
       { "x": 0.5, "y": 0.3, "z": -0.1, "visibility": 0.99 },
       ...
     ]
   }
   ```
   Массив `landmarks` — 33 элемента в формате MediaPipe (нормализованные 0–1; y вниз растёт).

3. **Авторизация и CSRF:**  
   Запросы с теми же учётными данными, что и на сайте (сессия или токен). Для Django: cookie `sessionid` + заголовок `X-CSRFToken` (значение взять из **GET** `/api/csrf-token/` перед первым POST).

4. **Ответ API (использовать как на сайте):**  
   ```json
   {
     "success": true,
     "count": 5,
     "stage": "up",
     "ready": true,
     "feedback": "Текст от тренера",
     "errors": [
       { "message": "Что не так", "hint": "Как исправить", "priority": 1 }
     ]
   }
   ```
   - **count** — показывать как счётчик повторений (или секунды для планки).  
   - **feedback** — выводить в блоке подсказок одной строкой.  
   - **errors** — отображать списком (до 2–4 штук), каждую с `message` и `hint`; сортировка по `priority`.

5. **Сохранение состояния:**  
   Состояние (count, stage, ready) хранится на сервере в `ActiveWorkout`. Сброс — **POST** `/api/ai/reset/` с `exercise_type`. Перед началом тренировки вызывать **POST** `/api/workouts/start/` с `exercise_type`.

6. **Завершение тренировки:**  
   По кнопке «Сохранить» вызывать **POST** `/api/workouts/complete/` с телом: `exercise_type`, `count`, `duration_seconds`, `errors_count` и т.д. (как в ТЗ_перенос_в_приложение.md). После успешного ответа — обновить квесты и статистику на бэкенде (они обновляются сервером); в приложении показать успех и вернуться на список тренировок или дашборд.

### 4.3. Альтернатива: локальный детектор

Допускается портировать логику из **`main/exercises.py`** (детекторы PushupWorkout, SquatWorkout и т.д., MathUtils, AngleSmoother, форматы ошибок) в приложение и считать повторения локально. В этом случае:

- Тексты подсказок и ошибок должны **совпадать** с сайтом (те же пороги углов, те же сообщения «что не так» / «как исправить»).
- Сохранение результата всё равно через **POST** `/api/workouts/complete/`, чтобы квесты и статистика обновлялись на сервере.

Предпочтительный вариант для стабильности и единообразия — использование **process-landmarks** на существующем backend.

### 4.4. Камера и производительность

- Запрос разрешения на камеру при первом входе на экран тренировки; при отказе — понятное сообщение и кнопка «Открыть настройки».
- Разрешение видео: достаточное для MediaPipe (например, 640×480 или 1280×720); ориентация портрет или ландшафт — по дизайну (рекомендуется портрет для телефона).
- Частота отправки landmarks: подобрать так, чтобы не перегружать сеть и сервер (например, 10–15 запросов в секунду), с сохранением плавного обновления счётчика и подсказок.

## 5. Остальной функционал (кратко)

- **Авторизация:** вход и регистрация по логину/паролю; после входа — приветственный экран (аналог `/welcome/`) или сразу дашборд.
- **Квесты:** отображение списка, прогресс, награды; вызовы API: GET `/api/quests/`, GET `/api/quests-data/`, POST start/cancel/complete.
- **Статистика:** использование GET `/api/stats/basic/`, `/api/stats/combined/`, `/api/stats/history/`, `/api/stats/daily/`, `/api/stats/exercise/` и отображение в удобном для телефона виде (графики, списки).
- **Профиль:** GET `/api/player/profile/`, POST `/api/player/upgrade-skill/` и т.д.; отображение уровня, XP, навыков, валюты, серии входов.
- **Лидерборд:** данные с бэкенда (если есть соответствующий API) или подготовить endpoint по ТЗ_перенос_в_приложение.md.
- **Конструктор тренировки:** диалог по шагам; **POST** `/api/workout-builder/chat/` с state и answer; отображение итогового плана (упражнения + рекомендуемые повторения).

Все API-контракты и форматы запросов/ответов — по документу **ТЗ_перенос_в_приложение.md**.

## 6. Критерии приёмки (мобильное приложение)

1. Приложение можно установить и открыть на телефоне (iOS и/или Android в зависимости от выбранного стека).
2. Все основные экраны (вход, дашборд, тренировки, квесты, статистика, профиль, настройки) реализованы и **подогнаны под телефон**: читаемый текст, удобные зоны нажатия, безопасные отступы, без «десктопной» вёрстки.
3. Внешний вид соответствует стилю сайта TeminaFit (цвета, карточки, градиенты, шрифты).
4. При выборе типа тренировки открывается экран с камерой; в реальном времени отображаются **счётчик повторений** (или секунды для планки) и **подсказки ИИ** (feedback + список errors с message и hint).
5. ИИ работает через **POST** `/api/ai/process-landmarks/` с landmarks с устройства (или через портированную логику `main/exercises.py` с теми же текстами и поведением).
6. Кнопка «Сохранить» завершает тренировку через **POST** `/api/workouts/complete/`; квесты и статистика на сервере обновляются.
7. Квесты отображают прогресс и награды; при выполнении цели квест завершается и награды начисляются.
8. Конструктор тренировки ведёт диалог и выдаёт план с упражнениями и рекомендуемыми повторениями.
9. Все тексты интерфейса и подсказки тренера — на русском языке.
10. Поведение подсчёта и подсказок **соответствует логике на сайте** (сглаживание, подтверждение фаз, приоритет ошибок, сообщения «почти правильно» и т.д.).
