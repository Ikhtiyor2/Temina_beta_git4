# ТЗ: Перенос веб-приложения TeminaFit в мобильное/нативное приложение

## 1. ОПИСАНИЕ ПРОЕКТА

**TeminaFit** — фитнес-приложение с игровыми элементами и ИИ-тренером. Пользователь выполняет упражнения перед камерой; система в реальном времени распознаёт позу (MediaPipe Pose), считает повторения, анализирует технику и выдаёт подсказки по ошибкам. Есть квесты, прокачка навыков, статистика, лидерборд и конструктор тренировок с учётом настроения и травм.

**Цель ТЗ:** перенести весь функционал текущего веб-сайта (Django + браузер) в мобильное приложение (или PWA/React Native/Flutter — на усмотрение исполнителя), сохранив логику ИИ, все экраны, API-контракты и поведение.

---

## 2. ТЕКУЩИЙ СТЕК

- **Backend:** Django 5.2, Python 3.10+, SQLite (можно заменить на PostgreSQL при переносе).
- **Frontend:** серверный рендеринг (Django templates), HTML/CSS/JS. Камера и распознавание поз — в браузере: MediaPipe Pose (CDN: `@mediapipe/pose`, `@mediapipe/camera_utils`, `@mediapipe/drawing_utils`).
- **Серверная часть ИИ:** опционально — при отправке кадров на сервер используется `main.pose_manager.PoseManager` (MediaPipe на Python) и `main.exercises` (правила по углам и подсчёт повторений). Основной сценарий: распознавание в браузере, на сервер отправляются только **landmarks** (ключевые точки), сервер возвращает count, feedback, errors.
- **Зависимости (Python):** Django, mediapipe, opencv-contrib-python, numpy, python-dotenv, whitenoise, gunicorn; остальное — см. `requirements.txt` в корне репозитория.

Методы: get_progress_percent, is_expired, check_completion, add_progress, complete_quest.
- **WorkoutSession** — факт тренировки: player, exercise_type, reps_count, errors_count, duration_seconds, calories_burned, date, quest (FK, nullable).
- **WorkoutSet** — сохранённый подход: user, exercise_type (PUSHUP, SQUAT, PULLUP, CRUNCH, PLANK), repetitions, date_completed, quality_score.
- **PlayerStats** — расширенная статистика (OneToOne с Player): total_workouts, total_reps, total_calories, total_workout_time; по упражнениям — pushups_total, squats_total, …; рекорды — max_pushups_set, max_squats_set, …; current_streak, max_streak, last_workout_date; today_reps, today_workouts, today_calories; perfect_workouts, quests_completed. ## 5. МАРШРУТЫ И API (полный список)

### 5.1. Страницы (GET)

- `/`, `/home/`, `/index/` — главная (home_page).
- `/login/`, `/signin/` — вход; `/register/`, `/signup/`, `/registration/` — регистрация.
- `/welcome/` — приветствие после входа; `/logout/`, `/signout/`.
- `/quick-login/`, `/demo/` — быстрый/демо вход.
- `/dashboard/` — личный кабинет; `/profile/` — профиль; `/workouts/`, `/training/`, `/exercises/` — список тренировок; `/workouts/create/` — конструктор тренировки с ИИ.
- `/quests/`, `/missions/` — квесты; `/stats/`, `/statistics/`, `/analytics/` — аналитика; `/leaderboard/`, `/rating/` — рейтинг; `/settings/`, `/account/` — настройки; `/skills/` — навыки.
- `/train/pushups/`, `/train/squats/`, `/train/crunches/`, `/train/planks/`, `/train/pullups/`, `/train/<exercise>/` — страница тренировки с камерой и ИИ (один шаблон training.html с параметром exercise).

### 5.2. AI API (критично для приложения)

- **POST** `/api/ai/process-landmarks/` — принять массив landmarks с клиента (MediaPipe 33 точки: x, y, z, visibility), тело запроса: `{ "exercise_type": "PUSHUP"|"SQUAT"|"CRUNCH"|"PLANK"|"PULLUP", "landmarks": [ { "x", "y", "z", "visibility" }, ... ] }`. Ответ: `{ "success": true, "count": int, "stage": "up"|"down", "ready": bool, "feedback": string, "errors": [ { "message", "hint", "priority" } ] }`. Состояние (count, stage, ready) хранится в ActiveWorkout и сохраняется между запросами.
- **POST** `/api/ai/process-frame/` (или `/api/ai/process/`) — альтернатива: отправка base64-кадра изображения; сервер сам прогоняет MediaPipe и детекторы. Тело: `{ "frame": "<base64>", "exercise_type": "PUSHUP"|... }`. Ответ расширенный (landmarks, pose_quality, processing_time_ms и т.д.). Для приложения предпочтительно использовать process-landmarks, чтобы не гнать видео по сети.
- **GET** `/api/ai/state/?exercise=PUSHUP` — текущее состояние упражнения (count, stage, ready, is_active, duration_seconds, workout_id).
- **POST** `/api/ai/reset/` (или `/api/ai/clear/`) — сброс состояния; тело: `{ "exercise_type": "PUSHUP"|... }`.
- **GET** `/api/csrf-token/` или `/api/csrf/` — получить CSRF-токен для последующих POST (если backend остаётся Django).

Все POST к AI и другим API требуют авторизации (session/cookie или токен) и при использовании Django — заголовок `X-CSRFToken` с значением из `/api/csrf-token/`.

### 5.3. Workout API

- **POST** `/api/workouts/start/` — начать тренировку; тело: `{ "exercise_type": "PUSHUP"|... }`. Создаёт/обновляет ActiveWorkout.
- **POST** `/api/workouts/complete/` — завершить тренировку; тело: `{ "exercise_type", "count", "duration_seconds", "errors_count" и т.д. }`. Сохраняет подход, обновляет квесты и статистику.
- **POST** `/api/save-set/<exercise_type>/` — сохранить подход (repetitions, quality_score).
- **GET** `/api/workouts/current/<exercise_type>/`, `/api/workouts/status/<exercise_type>/` — текущая активная тренировка.
- **POST** `/api/workouts/reset/`, `/api/workouts/clear/` — сброс.
- **POST** `/api/workout-builder/chat/` — чат с ИИ-конструктором тренировок; тело диалога (state, answer); ответ — следующий вопрос или итоговый план (список упражнений с url и reps).

### 5.4. Quests API

- **GET** `/api/quests/`, `/api/quests/all/` — список квестов.
- **GET** `/api/quests-data/` — данные для автообновления (активные квесты и т.п.).
- **POST** `/api/quests/start/` — взять квест; **POST** `/api/quests/cancel/` — отменить; **POST** `/api/quests/complete/`, `/api/quests/finish/` — завершить.

### 5.5. Stats API

- **GET** `/api/stats/`, `/api/stats/basic/` — базовая статистика.
- **GET** `/api/stats/history/`, `/api/stats/workouts/` — история тренировок.
- **GET** `/api/stats/daily/`, `/api/stats/activity/` — активность по дням.
- **GET** `/api/stats/exercise/`, `/api/stats/breakdown/` — разбивка по упражнениям.
- **GET** `/api/stats/combined/` — объединённые данные для дашборда.

### 5.6. Player API

- **GET** `/api/player/`, `/api/player/profile/` — профиль игрока (level, exp, skills, currency, streak и т.д.).
- **POST** `/api/player/upgrade-skill/`, `/api/player/upgrade/` — прокачать навык (strength, stamina, agility, technique); тело: `{ "skill_name": "strength"|... }`.
- **POST** `/api/player/add-currency/` — добавить валюту (для тестов/наград).
- **POST** `/api/player/update-streak/`, `/api/player/streak/` — обновить серию входов.

### 5.7. HUD API (при необходимости)

- **GET** `/api/hud/state/`, `/api/hud/status/`, `/api/hud/data/`, `/api/hud/`, `/api/hud/real-time/`, `/api/hud/unified/` — данные для HUD (счётчики, время, калории и т.д.).

Все перечисленные маршруты должны быть реализованы в приложении либо вызовом существующего backend по HTTP, либо перенесены в новый backend с сохранением форматов запросов/ответов.

## 6. ЛОГИКА ИИ-ТРЕНЕРА И УПРАЖНЕНИЙ

Полностью описана в `main/exercises.py`. Её необходимо воспроизвести на стороне приложения (или оставить на сервере и вызывать только `/api/ai/process-landmarks/`).

### 6.1. Общее

- **MathUtils.calculate_angle(a, b, c)** — угол в градусах в точке b (векторы ba и bc). Точки — объекты с полями x, y или списки [x, y].
- **AngleSmoother(size=5)** — очередь последних значений угла; метод **value()** возвращает медиану (сглаживание).
- **err(message, hint, priority)** — формат ошибки: message (что не так), hint (как исправить), priority (1 — критично, 2 — техника). В ответах API возвращать не более 4 ошибок за раз, отсортированных по priority.

### 6.2. Детекторы (классы)

Каждый детектор наследует PoseDetectionBase, ведёт состояние: count, stage ("up"/"down"), ready, ready_buffer (очередь булевых значений для подтверждения стартовой позы). Метод **_process_pose(landmarks)** возвращает `(feedback: str, errors: list[dict])`. Landmarks — объект с полем **landmark** — список из 33 элементов с атрибутами x, y, z, visibility (нормализованные 0–1; y вниз растёт). Индексы MediaPipe: 0 — нос, 11–12 — плечи, 13–14 — локти, 15–16 — запястья, 23–24 — бёдра, 25–26 — колени, 27–28 — лодыжки и т.д.

- **PushupWorkout**  
  Сглаживание: elbow, hip, back (AngleSmoother). Подтверждение смены фазы: 2 подряд кадра с smooth_elbow < 90 для перехода в "down", 2 кадра с smooth_elbow > 150 для выхода в "up". Проверки: руки на полу (запястья по y), кисти под плечами (по x), угол таза и спины в верхней точке, угол между локтями (не разводить), симметрия локтей, задержка в нижней точке (MIN_HOLD_FRAMES=2), форма корпуса в верхней точке. Сообщения «почти правильно» при down_hold_frames==1 и при hip_angle 128–135.

- **SquatWorkout**  
  Сглаживание knee; подтверждение фаз по smooth_knee (< 90 → down, > 170 → up). Проверки: колени не вперёд за носки (отдельно левое/правое), симметрия углов коленей, глубина приседа (min_knee_angle_in_rep < 100), задержка внизу (MIN_DOWN_FRAMES=5). «Почти» при min_knee_angle_in_rep 92–100.

- **CrunchesWorkout**  
  Стартовая поза: вид сбоку, тело в кадре, угол торса (плечи–таз–колени) > 168°. Учёт стабильности камеры, таз не отрывается. Фазы по углу торса (118° — вниз, 165° — вверх). Проверка угла шеи (подбородок не к груди).

- **PlankWorkout**  
  count = секунды в правильной позе. Линия плечи–таз–лодыжки ≈ 180° (допуск по углу провисания/пика таза). Локти/кисти под плечами. Стабильность (нет резких смещений центра). В ответах указывать фактический угол (например: «Угол линия плечи–таз–лодыжки: 165°»).

- **PullupWorkout**  
  Руки выше плеч в старте, корпус прямой. Подсчёт по углу в локтях (down → up при < 90°, засчёт при > 160°). Асимметрия локтей — отдельные сообщения.

Важно: при переносе на мобильный клиент либо вызывать только `/api/ai/process-landmarks/` и отображать приходящие feedback и errors, либо портировать целиком `exercises.py` (и при необходимости AngleSmoother, MathUtils) на язык приложения, сохранив пороги и тексты сообщений.

## 7. КАМЕРА И MEDIAPIPE В КЛИЕНТЕ

- В браузере используются скрипты: `@mediapipe/pose/pose.js`, `@mediapipe/drawing_utils/drawing_utils.js`, `@mediapipe/camera_utils/camera_utils.js` (CDN: cdn.jsdelivr.net). Инициализация: **Pose** с `locateFile: (file) => 'https://cdn.jsdelivr.net/npm/@mediapipe/pose/' + file`, затем **Camera(video, { onFrame: async () => pose.send({ image: video }) })**. Результаты: **results.poseLandmarks** — массив из 33 точек { x, y, z, visibility }.
- В приложении: использовать нативный SDK MediaPipe для iOS/Android (или веб-вью с тем же JS), получать poseLandmarks и либо отправлять их на `/api/ai/process-landmarks/`, либо обрабатывать локально портированной логикой из `exercises.py`. Отображение: видео с камеры + опционально скелет (drawing_utils) и блок с текстом тренера (feedback + errors: «Что не так», «Как исправить»). На экране тренировки обязательны: счётчик повторений (или секунды для планки), кнопки Пауза и Сохранить, блок подсказок ИИ с приоритизированным списком ошибок (до 2–4 на экране).

## 8. ЭКРАНЫ И ФУНКЦИОНАЛ (что перенести)

- **Авторизация:** вход, регистрация, выход, приветственный экран (welcome) после входа, при необходимости быстрый/демо вход.
- **Главная / дашборд:** краткая сводка (уровень, XP, серия входов, недавние тренировки), быстрые ссылки на тренировки и квесты.
- **Профиль:** уровень, опыт, навыки (сила, выносливость, ловкость, техника), валюта, достижения. Прокачка навыков за skill_points.
- **Тренировки:** список типов (отжимания, приседания, скручивания, планка, подтягивания) с кнопкой «Начать тренировку» → переход на экран тренировки с камерой и ИИ.
- **Экран тренировки:** один экран на все типы; параметр — exercise_type. Видео с камеры, оверлей со счётчиком и статусом («Загрузка модели», «Подключение камеры», «Готово»), блок подсказок тренера (feedback + errors с message/hint). Кнопки: Пауза, Сохранить (отправка на `/api/workouts/complete/` или save-set с count и типом упражнения). Таймер длительности. После «Сохранить» — обновление квестов и статистики на бэкенде.
- **Квесты:** список активных и завершённых квестов, прогресс (progress/goal), награды (XP, валюта, скилл-поинты), кнопки взять/отменить/завершить. Ежедневные квесты с expires_at.
- **Статистика:** сводка (всего тренировок, повторений, калорий, серии), история по дням/неделям, разбивка по упражнениям, рекорды. Использовать API stats (basic, history, daily, exercise, combined).
- **Лидерборд:** рейтинг игроков (по уровню, XP или по выбранной метрике).
- **Настройки:** учётная запись, тема, уведомления (если будут), выход.
- **Конструктор тренировки:** пошаговый диалог (настроение → травмы → уставшие мышцы); логика в `workout_builder.py` (get_next_question, apply_answer, build_plan). Итог — план: список упражнений с названием, ссылкой (url) и рекомендуемыми повторениями (reps). API: `/api/workout-builder/chat/`.

Навигация: нижняя или боковая панель с разделами Тренировки, Квесты, Аналитика (статистика), Профиль (и при необходимости Настройки, Главная).

## 9. КВЕСТЫ И ИГРОВАЯ МЕХАНИКА

- При регистрации/первом входе создаются начальные квесты (QuestManager.create_initial_quests, QuestGenerator.generate_initial_quests).
- Ежедневные квесты: до 4 в день, с expires_at; генерация через generate_daily_quests (если нет активных дневных).
- При сохранении тренировки вызывать обновление прогресса квестов (update_quest_progress по exercise_type и count). При достижении goal — complete_quest (начисление XP, валюты, скилл-поинтов).
- Серия входов (login_streak) обновляется при входе (update_login_streak). Квесты типа DAILY_LOGIN проверяются при входе (complete_daily_login).
- Усталость (fatigue): увеличивается при тренировке (add_fatigue), при необходимости уменьшается со временем/отдыхом. Квесты типа REST проверяют уровень усталости.

Логику квестов и генерации не менять при переносе; либо оставить на текущем backend, либо портировать QuestManager и QuestGenerator с сохранением форматов и правил.

## 10. ТРЕБОВАНИЯ К ПРИЛОЖЕНИЮ

1. **Платформа:** мобильное приложение (iOS и/или Android) или кроссплатформа (React Native, Flutter и т.п.); допустимо PWA с доступом к камере и тем же API.
2. **Backend:** допускается оставить существующий Django-сервер; приложение общается с ним по HTTPS. Либо реализовать новый backend с теми же контрактами API и той же бизнес-логикой (модели, упражнения, квесты, конструктор).
3. **Авторизация:** логин/пароль (и при необходимости регистрация). Сессии или JWT — как в текущем проекте или по согласованию; для Django — передача sessionid/cookies и X-CSRFToken для POST.
4. **Камера и поза:** использование MediaPipe для получения 33 ключевых точек в реальном времени; отправка landmarks на `/api/ai/process-landmarks/` с выбранным exercise_type и отображение возвращаемых count, feedback, errors. Либо локальный порт логики из `main/exercises.py` с теми же порогами и текстами.
5. **Контент и тексты:** все сообщения тренера, подсказки, названия упражнений и квестов — на русском языке, как в текущем коде (exercises.py, шаблоны, workout_builder).
6. **Офлайн:** по возможности кэшировать профиль и последние данные; при отсутствии сети — показывать понятное сообщение и не терять локально посчитанные повторения (при наличии локального детектора можно сохранять их и синхронизировать при появлении сети).
7. **Безопасность:** не хранить пароли в открытом виде; при использовании Django — соблюдать CORS и CSRF так, как настроено в проекте (CSRF_TRUSTED_ORIGINS и т.д.).

Исполнитель должен взять за основу репозиторий проекта (ветка master, полная копия). Ключевые файлы для переноса логики и воспроизведения API:

## 12. КРИТЕРИИ ПРИЁМКИ

- Пользователь может зарегистрироваться и войти.
- Отображаются дашборд, профиль (уровень, навыки, валюта), список тренировок, квесты, статистика, лидерборд, настройки.
- При выборе типа тренировки открывается экран с камерой; идёт распознавание позы (MediaPipe) и подсчёт повторений (или секунд для планки) в реальном времени; отображаются подсказки тренера (feedback и список errors с message и hint).
- После тренировки можно сохранить результат; при сохранении обновляются квесты и статистика на сервере.
- Квесты показывают прогресс и награды; при выполнении цели квест завершается и начисляются награды.
- Конструктор тренировки ведёт диалог (настроение, травмы, уставшие мышцы) и выдаёт план с упражнениями и рекомендуемыми повторениями.
- Все тексты интерфейса и тренера — на русском языке.
- Поведение подсчёта и подсказок соответствует логике в `main/exercises.py` (сглаживание, подтверждение фаз, приоритет ошибок, сообщения «почти правильно»).
